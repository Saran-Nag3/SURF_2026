# fizz - Design System

## Overview

Fizz is an unofficial Olipop design system covering foundations, navigation, commerce, reviews, editorial content, subscription flows, and homepage patterns.

- Source pages: All pages (5), including Getting Started With Fizz!, Foundations, and Components + Patterns.
- Base layout grid: 12 columns, 103.25px section, 16px gutter, stretch alignment.
- No local variable collections found.
- No spacing, radius, motion, or local effect-style variables found.

## Design language

- Brand character: fun and simple, using vibrant accents with dark green typography and generous editorial-scale headings.
- Display headings use Windsor EF Bold.
- Body copy, subheadings, and controls use Ano.
- Primary dark green: `#14423D` and `#18312A`.
- Warm cream surfaces: `#FFFAEF`, `#FFF7E5`, and `#FFF4CB`.
- Teal surfaces and accents: `#EDF6F3`, `#D3E8E3`, `#A7D1C5`, and `#008B6F`.
- Components frequently use pill-shaped controls with 32px radius.
- Product and editorial cards use rounded corners from 8px to 16px where specified.
- Use bright flavor and category colors for product navigation and promotional accents.

## Notes for implementers

- Use the named typography tokens instead of raw font sizes whenever a matching token exists.
- Preserve the distinction between Windsor EF Bold display headings and Ano body/control styles.
- Use only the documented colors; do not substitute near-identical greens or creams.
- Respect fixed component dimensions when reproducing the extracted desktop patterns.
- For responsive implementations, retain component hierarchy, typography relationships, and variant behavior while adapting layout.
- Treat image fills as source assets rather than inventing replacement colors.
- Flavor, category, state, size, theme, and icon variants are part of the component API; expose them explicitly.
- The source contains no spacing, radius, elevation, motion, or effect token collections. Use the explicit per-component values above only.
