# cred - Design System

## Overview

- CRED neoPOP community UI kit covering mobile navigation, payments, bills, credit cards, credit scores, rewards, offers, account settings, and transaction history.
- Source: Figma file “CRED's neoPOP UI kit (unofficial) (Community)”, all 11 pages.
- No local variable collections, spacing variables, radius variables, motion tokens, or local effect styles were found.
- Primary documented grid: mobile 12-column grid, 18px section alignment, 10px gutter.

## Design language

- Dark, high-contrast interface using `#0D0D0D`, `#121212`, and white text and iconography.
- Bright accent colors communicate rewards, success, offers, insights, and states.
- Gilroy is the primary UI typeface. PP Cirka is used for serif headings. Raw source usage also includes IBM Plex Mono.
- Use uppercase/caps styles with 2px tracking for compact labels and status text.
- Navigation is fixed-height and icon-led, with centered tab content and active-state variants.
- Cards are compact, information-dense, and frequently use fixed dimensions, outlined borders, or colorful backgrounds.
- The source includes both flat and stroked button styles, loading states, status tags, bottom sheets, and card variants.

## Screen patterns

- **Primary navigation:** dark 360x77px Nav bar with six Tab destinations and active-state treatment.
- **Home and rewards:** combine offer cards, Active booster cards, Brand logos, Card Bar, and spotlight content against dark surfaces.
- **Bills and payments:** use bill cards, Bill status tags, payment bottom sheets, statement rows, transaction cells, and explicit success/error states.
- **Credit cards and credit score:** pair Credit cards with Credit card statement, Credit Insights card, score detail impact cards, bureau logos, and score update CTA.
- **Explore and utility:** use Explore CRED list/grid patterns with 74x118px grid cells, icon families, and utility categories.
- **Profile and settings:** use Profile settings Bottom sheet, settings cells, Profile avatar, User, Settings, Info, Location, and CRED protect.
- **Empty and failure states:** use No Vouchers, Error, error, system error, and loading animation components.
- **Bottom-sheet flows:** use the documented payment and profile bottom-sheet families for focused tasks over the primary dark interface.

## Notes for implementers

- Use only the documented colors, type styles, dimensions, radii, and component families.
- Prefer semantic color tokens for state communication: success, info, warning, and error.
- Keep the interface predominantly dark with `#0D0D0D` and `#121212`; reserve bright accent families for cards, rewards, offers, and status emphasis.
- Use Gilroy for UI text and PP Cirka for serif-heading treatments. IBM Plex Mono appears in raw source usage and should only be used where a monospaced treatment is required by the source.
- Do not create a new spacing or radius scale; use the documented component-specific values.
- Preserve fixed component dimensions and variant names when recreating extracted components.
- Do not infer undocumented shadows, animations, breakpoints, responsive rules, or interaction behavior.
